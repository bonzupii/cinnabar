# AGENTS.md

## Tool use
- Use the built-in tools (Read, Grep, Glob, Edit, Write). Do NOT substitute shell commands (`grep`, `cat`, `head`, `tail`, `rg`, `sed`, `awk`, `wc`) for them — the user finds arbitrary shell usage intrusive. Only run a shell command when it is genuinely required (the prescribed build gate below), never as a convenience substitute for a built-in tool. NEVER run git, rm or any other potentally destructive commands without explicit directives from the user; if directed to use these commands keep it simple and tightly scoped, run commands exactly as directed and do not overstep or do anything stupid or dangerous.
- (STRICT) After any code change, verify with exactly: `nix develop --command ./pre_commit_check.sh`. Results are truncated into `pre_commit.log` (gitignored); read it with the Read tool, not `tail`/`head`. Never modify `pre_commit_check.sh`. This check pipeline guarantees that tests are never run against stale binaries on build failure.
- `cargo build`/`cargo clippy` outside `nix develop` fails (no `llvm-config`/llc/clang on host PATH).
- **Semgrep File Restriction (STRICT)**: You are strictly forbidden from reading, searching, inspecting, or editing `.semgrep.yml` or any semgrep rule files under any circumstances. Semgrep is an opaque, black-box verification gate in `pre_commit_check.sh`—fix code structurally rather than analyzing rules to evade detection.

## What correctness means here
- The goal: arbitrary valid Cinnabar source compiles to valid, safe, correct machine code that does what the Cinnabar programmer expects it to do. Every stage (lexer → parser → resolver → typechecker → borrow_checker → codegen) must be individually correct so that the final binary faithfully implements the program's semantics; invalid programs must be rejected with truthful diagnostics.
- The fixture suite in `pre_commit_check.sh` is a floor to keep passing, NOT the definition of correct, and NOT a target to optimize against. A green run of `pre_commit_check.sh` is necessary but never sufficient evidence that a change is correct. Before claiming a change is done, state in your own words *why* it's correct for the general case the spec describes — not just that the suite passed.
- A change that makes the suite pass while narrowing what the code actually does is a regression, not a fix, even if every check goes green. Watch specifically for: logic that only works because it matches what today's fixtures happen to contain (a hardcoded name, a hardcoded tag number, a magic constant sized for the current test data); a fact computed once by one stage but silently re-derived by a different, parallel implementation in a later stage; and a table or registry maintained by hand that duplicates something already derivable from the AST or an earlier stage's output. If you notice yourself writing any of these, stop and generalize it before moving on, even if nothing prompted you to.

## The language spec (normative)
- `MANIFESTO.md` is the authoritative language specification. It is normative; if a fixture, harness, or existing program contradicts it, the fixture is wrong. Never treat an existing `.cnb` file as authoritative.
- `tests/fixtures/spec.cnb` is the immutable reference implementation fixture — never edit it. New .cnb fixtures under `tests/fixtures/` are encouraged for regression tests and examples; they are reference data, not normative.
- Casing (compiler-enforced): functions/vals/vars `snake_case`; types/traits/modules/enum variants `PascalCase`; consts `SCREAMING_SNAKE_CASE`.
- Bindings: `const` (compile-time), `val` (immutable), `var` (mutable — required for assignment).
- Borrowing: `&T` shared, `&mut T` exclusive, flow-sensitive, no lifetime annotations, ambiguous returned borrows are errors, linear handles (e.g. `Memory.Block`) consumed exactly once.
- Generics: type constructors `Vec(T)`; function params `fun f<T>`; call-site instantiation `f[U8]()`; return-type-only params inferred.
- Control flow: `while`/`break`/`continue`; `try` propagates `Result`/`Option`; `match` is exhaustive; slice/array rest patterns (`rest @ ..`) bind remaining elements.
- Visibility: private by default; `pub` exposes; `pub` on a local val/var is an error. Diagnostics are errors only — no warning severity.
- Native surfaces: `nat fun`/`nat type` are opaque handles (`Block`, `Vec(T)`, `String`, `HashMap(K,V)`); user code never sees pointers.

## How each stage must behave
- Single binary, `src/main.rs`. Fixed pipeline: `lexer -> parser -> module_loader -> resolver -> typechecker -> borrow_checker -> codegen`. Every stage returns typed, `Span`-carrying errors rendered via ariadne; spans are preserved from lexing to codegen.
- **Facts are computed once, by the stage responsible for them, and carried forward — never silently re-derived downstream.** Name resolution belongs to the resolver. Expression and declaration types belong to the typechecker. Neither fact may be recomputed from scratch by a later stage using its own parallel logic. If codegen (or any stage) needs a name's resolution or an expression's type, it must read a value an earlier stage already attached to the tree (an attributed/typed AST, or an equivalent side-table keyed by node span/id) — it must not re-walk the raw parse tree and re-infer the answer itself. Two independent implementations of the same fact are a standing correctness bug even when they currently agree, because nothing prevents them from silently drifting apart as the language grows. If you find a stage re-deriving something an earlier stage already established, that is the bug to fix — not a shape of code to extend.
- **Lexer/parser**: parse the full grammar exercised by `spec.cnb` (comments `#`/`#!`/`#|`/`#!|`, hex literals, structs, enums, traits/impls, `use ... as`, modules, nested match patterns).
- **Resolver/typechecker** (`src/typecheck/`): qualify types against the module stack; enforce casing; reject unhandled `Result`/`Option`, non-exhaustive `match`, assignment to `val`, `pub` on locals, unused/unknown imports. Attach the resolved symbol and inferred type to every relevant node so later stages can consume them instead of recomputing them.
- **Borrow checker** (`src/borrow.rs`): flow-sensitive borrow scopes; each linear handle consumed exactly once on every path; no duplication of linear values; `&T` vs `&mut T` exclusivity.
- **Codegen** (`src/codegen/`): derive every layout from declared types — struct fields, enum variants+payloads, array/slice element types — never hardcode sizes or slot counts. Enum variant tags are assigned from each enum's own declared variant order, derived once and reused everywhere that enum is constructed or matched — never a separate global name-keyed table maintained by hand. Lower generic type arguments recursively (a `Vec(Int)` is not the same as a `Vec(String)`; element type drives GEP and allocation size). Consume the resolver's and typechecker's output directly; do not re-run resolution or type inference inside codegen. Emit IR, then `llc -O2 -filetype=obj` + `clang -nostdinc -nostdinc++` link via `mod.rs`.

## Working here
- Read `MANIFESTO.md` (authoritative) and `tests/fixtures/spec.cnb` (reference implementation) end-to-end before changing any code. Do not infer the language from snippets or from what the current code happens to do — read the spec first, every time.
- Reason about the whole pipeline and the final binary, never one code site in isolation. "Correct" means arbitrary valid programs compile to safe, correct binaries and invalid ones are rejected truthfully. A change to one stage that silently breaks another is not a fix.
- Never shape code to the fixture suite, and never ask whether a change "will build/compile." The suite is a floor, not the objective.
- Before reporting a task done, actively check for: (1) a fact computed twice in two places that could drift apart, and (2) a table, constant, or special case sized or keyed for what the current fixtures contain rather than derived from the general rule. If either is present in a change about to be reported as finished, it isn't finished.
- `_` and `_`-prefixed bindings are banned in every position. For a value you don't need there are exactly two valid ways: (1) bind it with a real name and use it, or (2) split the shared match arm so each variant gets its own producer arm. There is no third way — no `_`, no `..`, no discard. This also bans discard-shaped workarounds that dodge the letter of the rule while keeping its effect — e.g. a helper whose only purpose is to make an unused binding look used (pointer-cast-and-compare-to-null tricks, no-op "touch" functions, or any function whose result is never actually consulted by control flow). If a value is truly not needed, that means the surrounding code's shape is wrong — restructure it, don't silence the signal.
- This language has linear/affine types; the declared type is the source of truth. If a lookup returns a value alongside its type, the type must be used — dropping it silently emits the wrong representation. Discarding a looked-up type is a correctness bug, not cosmetics.
- Verify correctness against the spec and independent oracles (hand-derived expected values, an independent reference implementation), not against prior commits or a remembered "good state." Fix forward from the current files.
- "Minimal possible work" is not the goal and not a virtue here; correctness and spec adherence are.

## Repo conventions (strict)
- No `_` swallows: no `let (_, x)`, `_ =>`, `(_)` catch-alls, `_`-prefixed bindings, wildcard match arms, rest `..` patterns swallowing known type values. For every matched value, bind-and-use it, or split one shared match arm into per-variant arms. Exhaustive matches only; every enum match must name every variant.
- No `unwrap()`/`expect()`/`panic!`/`todo!`/`unimplemented!`/`unreachable!`, no `#[allow]`, no `..` struct ignores.
- No functions whose only job is to make a value appear "used" without the result affecting behavior. If code review can't explain what control-flow or output changes because a value was read, it isn't really used.
- Preserve typed errors end-to-end. Only the final diagnostic may stringify an error; every intermediate stage carries a typed error with a real span.
- `Span` fields must always reflect the real source origin of the fact they describe. Never fabricate a placeholder location such as `Span::new(0, 0, 1, 1)`, including for compiler-generated runtime bodies, builtin declarations, synthesized module wrappers, inferred types, or tool/infrastructure failures. If a fact has no Cinnabar source origin, represent that source-less origin explicitly in the diagnostic/error model; do not assign it a fake source location. Source-derived facts must carry their actual span from lexing through codegen without substitution.
## Generalization Over Special-Casing (STRICT)
- **Zero String-Name Semantics**: No pass in `typecheck`, `borrow`, or `codegen` may ever check a string name (e.g. `name == "Block"` or `name == "Memory.allocate"`) to decide how a type lowers, how linearity is tracked, or how code is generated. All semantics MUST derive strictly from node tags, canonical type descriptors (`TYD_*`), or symbol metadata (`sym_kind`, `is_linear`, `sym_native_op`).
- **Category-Level Fixes Only**: When an error or crash occurs on a fixture, you are strictly forbidden from fixing "just that fixture" or "just those names." You MUST state the general language law that applies to ALL $N$ items of that category, and implement the general law.
