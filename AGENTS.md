# AGENTS.md

## Tool use
- Use the built-in tools (Read, Grep, Glob, Edit, Write). Do NOT substitute shell commands (`grep`, `cat`, `head`, `tail`, `rg`, `sed`, `awk`, `wc`) for them — the user finds arbitrary shell usage intrusive. Only run a shell command when it is genuinely required (git, or the prescribed build gate below), never as a convenience substitute for a built-in tool.
- After any code change, verify with exactly: `nix develop --command ./pre_commit_check.sh`. Results are truncated into `pre_commit.log` (gitignored); read it with the Read tool, not `tail`/`head`. Never modify `pre_commit_check.sh`.
- `cargo build`/`cargo clippy` outside `nix develop` fails (no `llvm-config`/llc/clang on host PATH).

## What correctness means here
- The goal: arbitrary valid Cinnabar source compiles to valid, safe, correct machine code that does what the Cinnabar programmer expects it to do. Every stage (lexer → parser → resolver → typechecker → borrow_checker → codegen) must be individually correct so that the final binary faithfully implements the program's semantics; invalid programs must be rejected with truthful diagnostics.
- The fixture suite in `pre_commit_check.sh` is a floor to keep passing, NOT the definition of correct, and NOT a target to optimize against. A green run of `pre_commit_check.sh` is necessary but never sufficient evidence that a change is correct. Before claiming a change is done, state in your own words *why* it's correct for the general case the spec describes — not just that the suite passed.
- **A change that makes the suite pass while narrowing what the code actually does is a regression, not a fix**, even if every check goes green. This has happened before in this codebase (hardcoded layouts, dropped type args, a fixed 64-byte enum payload, a hand-maintained builtin function registry that shadowed the real declarations). If you notice yourself writing logic that only works because it matches what today's fixtures happen to contain — a hardcoded name, a hardcoded tag number, a magic constant sized for the current test data — stop and generalize it before moving on, even if nothing prompted you to.

## The language spec (normative)
- `tests/fixtures/spec.cnb` is the reference implementation of the language **and is immutable** — never edit it. Its header block comment is the spec. All other fixtures under `tests/fixtures/` are reference data, not source.
- Casing (compiler-enforced): functions/vals/vars `snake_case`; types/traits/modules/enum variants `PascalCase`; consts `SCREAMING_SNAKE_CASE`.
- Bindings: `const` (compile-time), `val` (immutable), `var` (mutable — required for assignment).
- Borrowing: `&T` shared, `&mut T` exclusive, flow-sensitive, no lifetime annotations, ambiguous returned borrows are errors, linear handles (e.g. `Memory.Block`) consumed exactly once.
- Generics: type constructors `Vec(T)`; function params `fun f<T>`; call-site instantiation `f[U8]()`; return-type-only params inferred.
- Control flow: `while`/`break`/`continue`; `try` propagates `Result`/`Option`; `match` is exhaustive; slice/array rest patterns (`rest @ ..`) bind remaining elements.
- Visibility: private by default; `pub` exposes; `pub` on a local val/var is an error. Diagnostics are errors only — no warning severity.
- Native surfaces: `native fun`/`native type` are opaque handles (`Block`, `Vec(T)`, `String`, `HashMap(K,V)`); user code never sees pointers.

## How each stage must behave
- Single binary, `src/main.rs`. Fixed pipeline: `lexer -> parser -> module_loader -> resolver -> typechecker -> borrow_checker -> codegen`. Every stage returns typed, `Span`-carrying errors rendered via ariadne; spans are preserved from lexing to codegen.
- **Facts are computed once, by the stage responsible for them, and carried forward — never silently re-derived downstream.** Name resolution belongs to the resolver. Expression and declaration types belong to the typechecker. Neither fact may be recomputed from scratch by a later stage using its own parallel logic. If codegen (or any stage) needs a name's resolution or an expression's type, it must read a value an earlier stage already attached to the tree (an attributed/typed AST, or an equivalent side-table keyed by node span/id) — it must not re-walk the raw parse tree and re-infer the answer itself. Two independent implementations of the same fact (e.g. one qualification/inference routine in the typechecker and a second, different one in codegen) are a standing correctness bug even when they currently agree, because nothing prevents them from silently drifting apart as the language grows. If you find a stage re-deriving something an earlier stage already established, that is the bug to fix — not a shape of code to extend.
- **Lexer/parser**: parse the full grammar exercised by `spec.cnb` (comments `#`/`#!`/`#|`/`#!|`, hex literals, structs, enums, traits/impls, `use ... as`, modules, nested match patterns).
- **Resolver/typechecker** (`src/typecheck/`): qualify types against the module stack; enforce casing; reject unhandled `Result`/`Option`, non-exhaustive `match`, assignment to `val`, `pub` on locals, unused/unknown imports. Attach the resolved symbol and inferred type to every relevant node so later stages can consume them instead of recomputing them.
- **Borrow checker** (`src/borrow.rs`): flow-sensitive borrow scopes; each linear handle consumed exactly once on every path; no duplication of linear values; `&T` vs `&mut T` exclusivity.
- **Codegen** (`src/codegen/`): derive every layout from declared types — struct fields, enum variants+payloads, array/slice element types — never hardcode sizes or slot counts. Enum variant tags are assigned from each enum's own declared variant order, derived once and reused everywhere that enum is constructed or matched — never a separate global name-keyed table maintained by hand. Lower generic type arguments recursively (a `Vec(Int)` is not the same as a `Vec(String)`; element type drives GEP and allocation size). Consume the resolver's and typechecker's output directly; do not re-run resolution or type inference inside codegen. Emit IR, then `llc -O2 -filetype=obj` + `clang -nostdinc -nostdinc++` link via `mod.rs`.

## Working here (traps that have been walked into)
- Read `tests/fixtures/spec.cnb` end-to-end BEFORE changing any code. Its header block comment is the spec; its body is the full grammar. Do not infer the language from snippets or from what the current (broken) code happens to do — read the spec first, every time.
- Reason about the whole pipeline and the final binary, never one code site in isolation. "Correct" means arbitrary valid programs compile to safe, correct binaries and invalid ones are rejected truthfully. A change to one stage that silently breaks another is not a fix.
- Never shape code to the fixture suite, and never ask whether a change "will build/compile." The suite is a floor, not the objective. (This codebase's codegen was historically tuned to the suite — hardcoded layouts, dropped type args, fixed 64-byte enum payloads, a hand-maintained function-signature registry duplicating what the AST already declared — and every one of those was wrong, not a shortcut.)
- Before reporting a task done, actively look for the two failure modes this codebase keeps producing: (1) a fact computed twice in two places that could drift apart, and (2) a table, constant, or special case sized or keyed for what the current fixtures contain rather than derived from the general rule. If either is present in a change you're about to report as finished, it isn't finished.
- `_` and `_prefix` bindings are banned in every position. For a field you don't need there are exactly two valid ways: (1) bind it with a real name and use it, or (2) split the shared match arm so each variant gets its own producer arm. There is no third way — no `_`, no `..`, no discard. This also bans discard-shaped workarounds that dodge the letter of the rule while keeping its effect — e.g. a helper method whose only purpose is to make an unused binding look used (pointer-cast-and-compare-to-null tricks, no-op "touch" functions, or any function whose result is never actually consulted by control flow). If a value is truly not needed, that means the surrounding code's shape is wrong — restructure it — not that the "unused" warning needs silencing.
- This language has linear/affine types; the declared type is the source of truth. If a lookup returns `(ptr, ty)` (e.g. `lookup_var`), `ty` must be used — dropping it silently emits the wrong representation. Discarding a looked-up type is a correctness bug, not cosmetics.
- Do not hunt git history for a "good state" to roll back to; the codebase has never been correct. Fix forward from the current files.
- "Minimal possible work" is not the goal and not a virtue here; correctness and spec adherence are.

## Repo conventions (strict)
- No `_` swallows: no `let (_, x)`, `_ =>`, (_) catch-alls, `_prefix` bindings, wildcard match arms, rest `..` patterns swallowing known type values. For every matched value, bind-and-use it, or split one shared match arm into per-variant arms. Exhaustive matches only; `BasicValueEnum`/`Expr`/`Type`/`ItemKind` matches must name every variant.
- No `unwrap()`/`expect()`/`panic!`/`todo!`/`unimplemented!`/`unreachable!`, no `#[allow]`, no `..` struct ignores.
- No functions whose only job is to make a value appear "used" without the result affecting behavior (see above). If code review can't explain what control-flow or output changes because a value was read, it isn't really used.
- Preserve typed errors end-to-end. Codegen uses `CodegenError { span, kind }` (`src/codegen/error.rs`) with typed variants for `BuilderError`, `io::Error`, and tool exit codes; only the final diagnostic may stringify, via `CodegenError::message()`.
- `Span` fields must always reflect the real source origin of the fact they describe. Never fabricate a placeholder location such as `Span::new(0, 0, 1, 1)`, including for compiler-generated runtime bodies, builtin declarations, synthesized module wrappers, inferred types, or tool/infrastructure failures. If a fact has no Cinnabar source origin, represent that source-less origin explicitly in the diagnostic/error model; do not assign it a fake source location. Source-derived facts must carry their actual span from lexing through codegen without substitution.
